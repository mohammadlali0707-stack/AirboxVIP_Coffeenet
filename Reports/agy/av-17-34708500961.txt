   - **Evidence:**
     - **Inline `callback_id`:** Line 128 dispatched `--field "callback_id=av-${{ github.event.issue.number }}-${{ github.run_id }}"` without capturing the value into a shell variable.
     - **Artifact Search Failure:** Lines 142–146 ran:
       ```bash
       mkdir -p /tmp/agy-out
       gh run download "$RUN_ID" --repo "$DISPATCH_REPO" --dir /tmp/agy-out 2>/dev/null || true
       OUT=$(find /tmp/agy-out -name "agy_output.txt" | head -1)
       [ -n "$OUT" ] && head -c 58000 "$OUT" > /tmp/final.txt || printf '%s\n' '(no output)' > /tmp/final.txt
       ```
       Because `agw-worker.yml` receives `target_repo`, it does not produce or upload an `agy_output.txt` artifact; instead, it directly commits the output file into the target repository at `Reports/agy/<callback_id>.txt` (e.g. `Reports/agy/av-16-34704736108.txt`). Consequently, `OUT` evaluated to empty, writing `(no output)` to `/tmp/final.txt`, which was then posted as the issue comment.
   - **Remediation:**
     - Capture `CALLBACK_ID="av-${{ github.event.issue.number }}-${{ github.run_id }}"` before calling `gh workflow run`.
     - Replace the `gh run download` block with a direct GitHub Contents API read of `Reports/agy/${CALLBACK_ID}.txt` using `GH_TOKEN="${{ secrets.GITHUB_TOKEN }}"`, decoding the base64 content into `/tmp/final_raw.txt` and truncating to 58,000 bytes.
